3.3 已否决方案及理由（不要重新引入）

否决 Qt + QML：本工程最初用 Qt 6.8.3 + QML 实现到阶段 2，因 QuickControls2 的 Basic 样式观感差、
  且 npm 生态完全用不上（贡献墙、月视图、日历全部要手写）而废弃。
否决 Qt + WebEngine 混合渲染：Qt WebEngine 打包整个 Chromium，产物增加 150–200MB、常驻多占 150MB+ 内存，
  与"小体积、低内存、快启动"硬约束直接冲突。
否决 Electron：同样打包 Chromium（100MB+ 体积），且常驻内存高于 Tauri。
选 Tauri 2 的理由：调用系统自带 WebView2、不打包浏览器内核，安装包约 10MB，
  同时完整保留 React 与 npm 组件生态 —— 是本工程唯一同时满足"小体积"与"组件生态"的方案。

四、数据模型（严格按此结构实现）
4.1 存储位置
目录 %APPDATA%/DailyTodo/（不使用安装目录，避免权限问题）

tasks.json —— 任务主数据
settings.json —— 软件配置

4.2 tasks.json 结构
{
"version": 1,
"tasks": [
{
"id": "uuid-v4",
"title": "任务标题",
"note": "文字描述",
"createdAt": "ISO8601",
"schedule": {
"type": "once | workday | weekend | daily",
"startDate": "YYYY-MM-DD",
"endDate": "YYYY-MM-DD 或 null"
},
"instances": {
"YYYY-MM-DD": { "done": true, "doneAt": "ISO8601 或 null" }
},
"reminder": { "enabled": true, "time": "HH:mm" },
"archived": false
}
]
}
说明：周期任务不展开成多条记录，用 schedule + instances 映射，避免数据膨胀。渲染某一天时先按 schedule 判定该日期是否应出现，再查 instances 取完成状态。

4.3 写入规范

先写 .tmp 文件再原子替换，防止写一半崩溃导致数据损坏
启动时校验 version 字段；文件损坏则自动读取最近一份备份并提示用户
所有日期用本地时区的 YYYY-MM-DD 字符串，禁止用时间戳做日期主键
五、核心功能需求（仅开发以下功能）
5.1 任务管理

默认展示今日待办
新建 / 完成 / 取消完成 / 删除；任务支持标题 + 文字描述
已完成任务置灰 + 细划线，支持折叠或隐藏已完成
删除需二次确认并可撤销（撤销仅当次会话有效，不做全局 undo 栈）
删除落库语义 = 归档：删除即置 archived = true，任务不再出现在任何日期的待办与完成率分母中，
  但 instances 历史记录保留，贡献墙历史格子不会因删除而缺洞；支持从归档列表恢复
5.2 双视图与周期任务

日视图 / 月视图切换；日视图列当日全部待办；月视图按天展示完成情况，无任务日期弱化处理
周期规则四选一：仅一次、工作日、非工作日、每天
执行日期可选：今日 / 明日 / 自定义日期
本地系统通知提醒，不同周期任务各自生效；提醒由本机计时器触发，不做常驻后台服务、不做分钟级轮询
5.3 节假日与工作日判定（重点，按此实现）

判定优先级：本地缓存 holidays_YYYY.json > 联网刷新 > 降级规则
降级规则：无任何数据时，周一至周五视为工作日，周六周日视为非工作日
联网策略：仅在「新增或修改周期任务」且本地无当年数据时主动请求一次；设置页提供手动「刷新节假日」按钮
数据源：URL 可配置，默认读取 holiday-cn 静态 JSON（国务院公告口径，全国法定节假日，无地区特殊口径）
  默认 URL 模板：https://cdn.jsdelivr.net/gh/NateScarlet/holiday-cn@master/%1.json（%1 为四位年份）
  数据格式（holiday-cn 原始格式）：{ "year": 2026, "days": [ { "date": "2026-01-01", "name": "元旦", "isOffDay": true } ] }
  调休上班日在数据中以 isOffDay = false 出现，必须正确识别为工作日
  超时 5 秒，失败静默降级，不阻塞 UI、不弹错误框；URL 留空即退化为「永不联网」
绝对禁止：后台定时联网、启动自动联网、任何数据上传
5.4 数据持久化

任务、贡献墙数据、配置全自动保存，关闭软件不丢失
每天首次启动生成一份备份，滚动保留 7 份
支持手动导出 / 导入 JSON 备份；导入前校验结构，冲突时让用户选择覆盖或合并
无云上传、无使用统计、无隐私收集
5.5 窗口与托盘

普通窗口 / 桌面悬浮窗双模式切换
悬浮窗：置顶、可拖动、可缩放、边缘吸附
最小化到系统托盘后台常驻；需单实例检测，二次启动直接唤起已有窗口
失焦自动隐藏或切换迷你模式（设置项可关）
5.6 贡献墙

日历色块展示每日完成率，完成率 = 当日已完成数 / 当日应完成数
完成率分 5 档，色阶递进；0% 为极低透明度底色
支持查看历史完成数据
5.7 桌宠

独立悬浮窗口，常驻桌面顶层，可拖动，半透明
鼠标悬浮：轻微缩放动效 + 弹出当日待办清单与完成统计；鼠标移开淡出消失
桌宠与主窗口同一进程（禁止子进程），主窗口崩溃时桌宠随进程退出，不留孤儿窗口
5.8 主题

浅色 / 深色切换，覆盖主窗口、悬浮窗、桌宠弹窗、贡献墙、月视图
切换即时生效，不留错乱；所有颜色走 CSS 变量（定义在 src/styles/theme.css），
  禁止在组件里硬编码颜色值
六、视觉 UI 设计规范
整体：极简干净、低饱和度、磨砂质感、商务简约，贴合 Windows 原生观感。

窗口：主窗口 / 悬浮窗 / 桌宠弹窗统一圆角，无生硬直角；层级顺序 弹窗 > 悬浮窗 > 主窗口
