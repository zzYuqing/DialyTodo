# 特殊周期（ScheduleType = "special"）设计文档

> 阶段 7（功能完善）新增需求。本文档为设计方案定稿，开发前以此为准。
> 关联：`src/types/task.ts` 的 `Schedule`、`src/lib/schedule.ts` 的 `occursOn`、
> `src/constants/schedule.ts` 的文案表、`src/lib/validate.ts` 的 `normalizeTask`。

## 1. 背景与目标

现有 5 种周期（once / daily / workday / weekend / weekly）覆盖面有限：
- `daily` 只能「每天」，`weekly` 只能「每周指定星期且间隔恒为 1」，
  表达不了「每 3 天」「每 2 周周一三」「每月 15 号」「每月最后一个周五」这类高频场景。

目标：新增一种**特殊周期**，参考 cron 表达式生成器的「重复模式」思路，但
**砍掉分钟/小时/秒**（任务只需日级），且**不生成真实 cron 表达式**，只建模
「单位 × 间隔 × 锚点」三要素，给出人类可读文案与命中判定。

## 2. 方案决策（来自方案讨论）

| 决策点 | 结论 |
|--------|------|
| 覆盖范围 | **天 / 周 / 月** 三档（本期**不含年**） |
| 与现有类型关系 | **独立追加**第 6 种 `type="special"`，原 5 种原样保留，不整合 |
| 月锚点形态 | 「指定几号」+「第几个星期几」两者都支持 |
| 节假日感知 | **纯日历，不感知**节假日/调休（与 `weekly` 一致） |

## 3. 数据结构

在 `Schedule` 上新增一块 optional 的 `special`。其余 5 种 type 的 `special` 恒为
`undefined`，不污染老数据。

```ts
// src/types/task.ts —— Schedule 新增
special?: {
  unit: "day" | "week" | "month";          // 本期不含 "year"
  interval: number;                         // 每隔 N 个 unit，>=1，UI 限 1..99
  weekdays?: number[];                      // unit=week：命中星期，0=周一…6=周日
  monthDays?: number[];                     // unit=month：命中日期 1..31（多选）
  monthWeekday?: {                          // unit=month：第几个星期几
    ordinal: 1 | 2 | 3 | 4 | 5;             // 5 = 最后一个（当月不足 5 个则取实际最后一个）
    weekday: number;                        // 0=周一…6=周日
  }[];
  monthLastDay?: boolean;                   // unit=month：命中「每月最后一天」（自动取当月末日，大小月/2月均适用）
};
```

## 4. 判定语义

`startDate` 同时是**区间起点**（`isWithinRange`）和**周期锚点**（第 0 次基准）。
命中前先过区间过滤，再按 `unit` 分派。

| unit | 命中规则 | 锚点字段 |
|------|---------|---------|
| `day` | `天数差(start,date) % interval === 0` | 无（纯间隔） |
| `week` | `周序号差(start,date) % interval === 0` 且 `weekday(date) ∈ weekdays` | `weekdays` |
| `month` | `月份差(start,date) % interval === 0` 且（`date日 ∈ monthDays` 或 `monthLastDay` 命中末日 或 命中 `monthWeekday`） | `monthDays` / `monthLastDay` / `monthWeekday` |

- `day`：`start` 当天算第 0 次命中，之后每 N 天一次。
- `week`：**cron 式周对齐**——以 `start` 所在周为第 0 周，周边界用现有周一制
  `weekdayIndexOf`（周一=0）。「每 2 周周一」= 每隔一周的周一。
- `month`：`start` 所在月为第 0 月，月份差按整月算（跨年正确）。

## 5. 边界规则

### 5.1 短月缺日 —— 前端直接禁用选择（重点）

`monthDays` 若包含 **29 / 30 / 31** 中任一日期，这些日期在部分月份不存在
（2 月无 29/30/31，4/6/9/11 月无 31）。按 cron 行为，缺日月份会**静默不触发**，
属于易踩坑的隐蔽失效。

**决策：不在判定层兜底，也不在提交层才警告，而是前端直接禁止选择 29/30/31。**

- 月锚点的「指定几号」数字盘里，29/30/31 三个 chip **默认禁用**（`disabled`），
  hover 提示「2 月 / 小月无此日，禁止选择」。用户从 UI 根本无法把 29/30/31 选入新配置。
- 为兼容存量老数据（可能之前已写入 29/30/31），禁用的判定采用
  `disabled = day >= 29 && !已选中`：即「未选时禁用、已选中时可取消」——
  老数据载入后能看到并移除该值，但无法再新增。
- 判定层（`occursOnSpecial`）对 `monthDays` 仍保留「短月自然跳过」的宽松行为，
  因此即便老数据残留 29/30/31，也不会报错或被判废，只是小月静默不触发（与 cron 一致）。
- `monthWeekday`（第几个星期几）天然安全（每月必有第 1~4 个星期几，
  `ordinal=5` 取实际最后一个），**不受此限制**。
- 「每月最后一天」需求由 5.4 的 `monthLastDay` 承接，不再需要冒险选 29/30/31。

### 5.2 「最后」的表达

`monthWeekday.ordinal = 5` 表示当月最后一个该星期几（如「每月最后一个周五」=
`{ ordinal: 5, weekday: 4 }`）；当月不足 5 个时取实际最后一个。

### 5.3 周对齐口径

采用 cron 式周对齐（见 4. `week`），而非「从 start 起每 7×N 天滑动窗口」。
理由：与用户熟悉的 cron 生成器语义一致，且「每 2 周周一」落到固定星期更符合直觉。

### 5.4 最后一天（monthLastDay）

`special.monthLastDay = true` 时，任务在**每月最后一天**命中，不论大小月 / 闰年 2 月，

判定用 `isLastDayOfMonth(dateKey)`：`date.getDate() === new Date(y, m+1, 0).getDate()`，
自动取到正确末日（2 月 28/29、小月 30、大月 31 都正确），无需用户关心当月天数。

- 与 `monthDays`（固定几号）互补：固定几号在短月会失效，而 `monthLastDay` 永远有值。
- UI 表现：月锚点数字盘末位（31 之后）有一枚「最后一天」chip，点击切换 `specialMonthLastDay`。
  「最后一天」与「指定几号」「第几个星期几」可叠加（如「每月 1 号 和 最后一天」）。
- 文案：`describeSpecial` 在 month 段追加「最后一天」，如「每月 1、15 号、最后一天」。

## 6. 与现有机制的交互边界

| 关注点 | 决策 | 理由 |
|--------|------|------|
| `completedAt`（长期一次性完成） | special **不写** `completedAt` | 它是无限重复任务，单日完成走 `instances`，与 daily/weekly 同口径 |
| DDL 紧迫度染色（`lib/ddl.ts`） | special **不参与** | `isLongDdlTask` 仍只看 `once`；特殊周期就是普通周期的高阶版 |
| 节假日/调休 | **不感知** | 纯公历计算，与 `weekly` 一致；不调用 `isWorkday` |
| `describeSchedule` 文案 | 新增 `describeSpecial` | 见 8. 文案示例 |

## 7. 工具函数需求（开发阶段复用/新增）

- `daysBetween(a, b)`：已有或新增，用于 `day`。
- `weekIndexSince(start, date)`：以周一制周边界算「第几个周」，用于 `week`。
- `monthDiff(start, date)`：整月数差（跨年正确），用于 `month`。
- `nthWeekdayOfMonth(date, ordinal, weekday)`：判断 `date` 是否当月第 `ordinal` 个 `weekday`，用于 `monthWeekday`。

## 8. 文案示例（describeSpecial）

| 配置 | 文案 |
|------|------|
| {unit:day, interval:3} | 每 3 天 |
| {unit:week, interval:2, weekdays:[0,2,4]} | 每 2 周 周一、周三、周五 |
| {unit:month, interval:1, monthDays:[1,15]} | 每月 1、15 号 |
| {unit:month, interval:1, monthWeekday:[{ordinal:2,weekday:0}]} | 每月第 2 个周一 |
| {unit:month, interval:1, monthWeekday:[{ordinal:5,weekday:4}]} | 每月最后一个周五 |
| {unit:month, interval:1, monthDays:[1,15], monthLastDay:true} | 每月 1、15 号、最后一天 |
| {unit:month, interval:1, monthLastDay:true} | 每月最后一天 |

## 9. 数据兼容性（项目铁律）

新增 `special` 块整体 optional，严格走三板斧：

1. **边界校验判空**用 `!= null`（同时放过 null/undefined），禁止 `!== null`。
2. **加载时 normalize 补全缺失字段**：`normalizeTask` 对缺省 `special` 补 `undefined`；
   对存在的 `special` 校验并补全 `unit`/`interval`/各锚点数组（缺失数组补 `[]`）。
3. **新建对象显式带新字段**：`createTask` 在构造 `Schedule` 时显式写 `special: undefined`
   （或用户表单值），保持读写一致。
4. 加完后用备份目录里的老格式文件验证一遍再交付。

`occursOn` 的 `case "special"` 先判 `schedule.special != null`，否则返回 `false`
（防御性，理论上 `type==="special"` 必有，但保持与 `weekdays` 同口径）。
