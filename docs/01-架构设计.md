## 三、分层职责与依赖方向

依赖只能自上而下，**反向依赖一律视为缺陷**：

```
views / components / pet   →  stores  →  lib（纯）+ services（副作用） →  bridge  →  Rust
```

三条硬规则（建议后续用 ESLint import 规则固化）：

1. **`src/lib/**` 禁止 import** `@tauri-apps/*`、`react`、`zustand`。
   只允许 `date-fns` 与本项目的 `types/` `constants/`。
   这是"业务逻辑可独立测试"的唯一保障，也是评级标准。
2. **`src/services/**` 是唯一可以碰宿主能力的地方**，且必须通过 `bridge/` 调用，不得直接 import 插件包。
   （唯一例外：`@tauri-apps/plugin-fs` 的读写原语由 `services/storage.ts` 直接使用。）
3. **组件不得直接读写 store 以外的任何数据源**，不发 fetch、不读文件。

`lib/` 与 `services/` 的协作方式：`lib/schedule.ts` 的 `occursOn(schedule, date, isWorkday)`
接收一个 `isWorkday` 回调，由调用方（store）从 `useHolidayStore` 注入。
这样周期规则与数据来源彻底解耦 —— 单测时传个 `() => true` 就能跑。

## 五、Rust 边界：command 清单

严格遵守 3.5：源文件 3 个（`main.rs` / `lib.rs` / `commands.rs`），单函数 ≤ 50 行。

`commands.rs` 计划 5 个 command，每个都是薄封装：

| command | 作用 | 为什么需要 Rust |
| --- | --- | --- |
| `show_main_window` | 从托盘恢复并聚焦主窗口 | WebView 无法 unminimize 自身之外的窗口 |
| `switch_window_mode(mode)` | 普通窗口 ↔ 悬浮窗形态切换 | 需改 decorations / resizable / alwaysOnTop / shadow 等窗口标志 |
| `toggle_pet_window` | 显示 / 隐藏 / 创建桌宠窗口 | 桌宠窗口由 Rust 创建并持有 handle |
| `set_pet_ignore_cursor(ignore)` | 桌宠鼠标穿透 | 宿主窗口标志 |
| `quit_app` | 退出（先销毁桌宠再退） | 满足 5.7"主窗口崩溃时桌宠随进程退出，不留孤儿窗口" |

`lib.rs` 负责：插件注册、托盘菜单构建、single-instance 回调、窗口创建时应用磨砂。
`main.rs` 只做入口转调。

### 5.1 capabilities/default.json 权限（最小权限）

- `core:default`、`core:window:allow-*`（窗口控制所需的最小子集）
- `fs`：作用域限定 `$APPDATA/DailyTodo/**`，禁用 `$HOME/**`、`$DESKTOP/**` 等通配
- `dialog`：`allow-open` / `allow-save`
- `notification`：`default`
- `autostart`：`allow-enable` / `allow-disable` / `allow-is-enabled`
- `opener`：`allow-open-path`，作用域限定 `$APPDATA/DailyTodo/**`

`tauri-plugin-single-instance` 与 `window-vibrancy` 不暴露给前端，无需 capability 声明。

### 6.1 `store/` 还是 `stores/`

提示词第十节写的是单数 `store/`，LWWFLM8Plus 用的是复数 `stores/`。
**建议用 `stores/`**，理由是 3.1 明确要求"目录组织参考 LWWFLM8Plus 保持一致以降低维护成本"。
若你更看重提示词字面，我可以改回 `store/`。

### 6.2 是否允许新增 2 个 postcss 依赖

LWWFLM8Plus 没配 postcss，但本工程提示词要求"所有颜色走 CSS 变量"（5.8）与
"组件中禁止硬编码颜色与尺寸"（十三节）。建议新增：

- `postcss` + `postcss-preset-mantine` + `postcss-simple-vars`

作用：Mantine 的 `light-dark()` 函数支持、rem → px 转换、CSS 变量写法简化。
不加也能跑，但主题切换的代码会啰嗦不少。请确认是否同意引入。

### 6.3 提醒的进程存活前提

按 5.2"不做常驻后台服务、不做分钟级轮询"实现后，**完全退出应用期间不会触发提醒**。
托盘常驻时正常。这符合"轻量"定位，但如果你希望关机/退出后仍能提醒，
需要引入计划任务或常驻服务 —— 与第八节硬约束冲突，我不建议。请确认按哪种走。

### 6.4 桌宠需要第二个 Vite 入口

5.7 要求桌宠是**独立窗口**（与主窗口区分），因此：
- `vite.config.ts` 配 `build.rollupOptions.input = { main: 'index.html', pet: 'src/pet/pet.html' }`
- `tauri.conf.json` 定义两个窗口：`main`（普通/悬浮双形态，共用一个 WebView）与 `pet`

注意：`tauri.conf.json` 目前尚不存在（阶段 2 新建）。新建后按 `AGENTS.md` 第四节，
其窗口尺寸、productName、identifier、bundle 配置将纳入禁改清单。
