## 阶段 2 第二轮修复：QML 跨目录类型不可见（14:53）

运行时崩溃：`qrc:/DailyTodo/qml/App.qml:94:9: DayView is not a type`。

**根因**：`qt_add_qml_module` 把所有 QML 编进同一模块，但 QML 引擎的**隐式 import 只覆盖同目录文件**。App.qml 在 `qml/`，DayView 在 `qml/view/`、Theme 在 `qml/theme/`、TaskItem 在 `qml/component/`，跨目录互相不可见。

**修复**：显式相对目录 import——App.qml 加 `import "theme"` + `import "view"`；DayView.qml 加 `import "../theme"` + `import "../component"`；TaskItem.qml 加 `import "../theme"`。相对导入对 qrc + qmlcachegen 均有效，不动模块 URI。

**教训：QML 文件按目录分包（theme/view/component）时，凡引用非同目录类型，必须写相对 import。新加 QML 文件时检查它引用了哪些跨目录类型。**

## 环境排查：首次 `tauri dev` 报 cargo metadata not found

**现象**：`npm run tauri dev` → `failed to run 'cargo metadata' ... program not found`；`where link.exe` 无输出。

**诊断结论（已用 vswhere + 目录探测 + 注册表 PATH 核实）**：
- 本机环境已齐备，**无需补装任何东西**：
  - VS Community 2026，**装在非默认路径 `D:\VisualStudio\Product`**（不是 C 盘 Program Files）
  - MSVC 工具集 `14.51.36231`，`link.exe`/`cl.exe` 在 `D:\VisualStudio\Product\VC\Tools\MSVC\14.51.36231\bin\Hostx64\x64\`
  - Windows 11 SDK `10.0.26100.0`，`kernel32.lib`/Include 齐全
  - Rust 已装：`C:\Users\BF060\.cargo\bin` 全套（cargo/rustc/rustup），且已写入用户级 PATH（注册表 `USER_HAS_CARGO=True`）
- **根因**：Rust 装好后，已启动的 VS Code 集成终端 PATH 快照未刷新（Windows 环境变量仅在进程启动时从注册表拷贝）。`where link.exe` 无输出属正常——link.exe 本就不在 PATH，cargo 编译时 rustc 会自动经 vswhere 定位 MSVC + SDK。

**解决**：重启终端（或重启 VS Code）刷新 PATH 即可，`cargo --version` 验证后直接 `npm run tauri dev`。

**环境关键事实（后续阶段可能复用）**：VS 在 D 盘非常规路径；MSVC 14.51；SDK 26100。
